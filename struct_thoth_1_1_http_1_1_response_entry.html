Detailed Description

template<MethodConcept Method = GetMethod, BodyConcept Body = std::string>
struct Thoth::Http::ResponseEntry< Method, Body >

Request's evil twin designed to help in conversions.

Many libraries develop ways to convert from a "body like element" directly to a Request, even when the value isn't of the same type of the body itself. C++ doesn't have Rust's/Haskell's traits or prototypes, but we can achive this by using conversions and CPOs. We can't use conversion operators directly because we don't have the control of every target type (like std::string or const char), and isn't possible to make template conversion constructor for Request and Response while keeping these types aggregates. The solution is to merge both strategies in "evil twin versions" of Request / Response, these types acts like a bridge between your body-like and the request/response object.

Of course, the CPO itself isn't tied to a specific MethodConcept, but RequestEntry and ResponseEntry are in order to mimic exatly the behavior of their counterpart, you can change GetResponse<> Func(GetRequest<> req) to GetResponseEntry<> Func(GetRequest<> req) with minimal changes.
