Which sides of an exchange a body can feed, the minimum BodyIo surface an erased body promises.

In = the transport pushes wire bytes in (Write + FinishWrite, the Server request side). Out = the transport pulls slices out (Size + Read, the Server response side). Both = the body models both directions at once (symmetric bodies, a proxy pipe, an echo buffer).

◆ Decompress()

template<class Next>
auto Thoth::Http::Decompress ( Next next)

Wraps a handler to reverse Content-Encoding on the response body (RFC 9110 §8.4). Undoes codings in reverse application order.

  • Supported: gzip and deflate (via zlib).
  • Unsupported: br and zstd (returns an error as no codec is linked yet).
Note
Scoped strictly to Body = std::string. Decompressing directly into an arbitrary streaming sink would need the codec itself to stream, which this doesn't do.

NextInner handler.

◆ ReceiveHead()

template<CommonSocketConcept Socket>
exec::task< Exchange< Socket > > Thoth::Http::ReceiveHead ( ReadContext< Socket > & context,
const HostPolicy & hosts )

Reads one request head and validates it, producing a live Exchange for the Router or the ThothError that explains the refusal.

The framing is computed here, once, so nobody re-parses headers to reason about the body later. A refused head is thrown as a plain ThothError carrying the StatusCodeEnum to answer with (413 for an oversized Content-Length, 400 for a Host outside the policy), which is everything the caller needs to answer, no intermediate error type between the head and the wire. Anything the transport throws collapses into the same shape, a ConnectionErrorEnum inside means the socket itself died mid-read and there is nobody left to answer.
